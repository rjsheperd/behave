* Overview
** Scope

This document is a comprehensive roadmap for porting the BehavePlus fire behavior
library from C++14 to Rust. The C++ source lives in =src/behave/= and consists of:

- *41 header files* (.h)
- *41 implementation files* (.cpp) (including 1 header-only file: =surfaceInputEnums.h=)
- *~28,000 lines* total (calculations + data tables)
- *Zero external dependencies* beyond the C++ standard library

The library implements the Rothermel fire spread model and related fire science
algorithms: surface fire, crown fire, spotting, ignition, containment, mortality,
and environmental tools.

** Architecture: C++ → Rust Mapping

| C++ Concept             | Rust Equivalent                              |
|-------------------------+----------------------------------------------|
| Class with members      | =struct= + =impl= block                     |
| Class hierarchy         | Composition + traits                         |
| =enum struct=           | =enum= with =#[derive]= macros              |
| Static class methods    | Module-level functions or associated fns     |
| Header + .cpp pair      | Single =.rs= module file                    |
| =std::vector<T>=        | =Vec<T>=                                     |
| Raw pointers / refs     | Owned values or =&= / =&mut= references     |
| =const= static arrays   | =const= arrays or =phf= compile-time maps   |
| Namespace               | Rust =mod=                                   |
| Exception (none used)   | =Result<T, BehaveError>=                     |

** Guiding Principles

1. *Numerical parity first* — every ported function must produce identical outputs
   to the C++ for known inputs before any refactoring
2. *No inheritance* — use composition and traits instead of class hierarchies
3. *Immutable by default* — prefer =&self= methods; use =&mut self= only when needed
4. *Error handling* — =Result<T, BehaveError>= at public API boundaries; panics only
   for programmer errors (invariant violations)
5. *Zero =unsafe=* — unless absolutely required for FFI
6. *Test-driven* — port tests from =testBehave.cpp= alongside each module
7. *Phase ordering* — respect dependency graph; foundation types must exist before
   anything that uses them

* Rust Design Decisions

** Enum Translation

C++ uses =enum struct= with integer backing. In Rust:
#+begin_src rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
#[repr(u32)]
pub enum FuelLifeState {
    Dead = 0,
    Live = 1,
}
#+end_src

** Unit Conversion Trait

Replace static methods with a trait:
#+begin_src rust
pub trait UnitConversion: Copy {
    fn to_base(self, value: f64) -> f64;
    fn from_base(self, value: f64) -> f64;
}

impl UnitConversion for LengthUnits {
    fn to_base(self, value: f64) -> f64 {
        match self {
            LengthUnits::Feet => value * 0.3048,
            LengthUnits::Meters => value,
            LengthUnits::Miles => value * 1609.344,
            LengthUnits::Kilometers => value * 1000.0,
            LengthUnits::Chains => value * 20.1168,
        }
    }
    // ...
}
#+end_src

** No Inheritance — Composition + Traits

C++ =SurfaceFire= owns =SurfaceFuelbedIntermediates= and =SurfaceFireReactionIntensity=.
In Rust, same pattern via struct composition:
#+begin_src rust
pub struct SurfaceFire {
    fuelbed: SurfaceFuelbedIntermediates,
    reaction: SurfaceFireReactionIntensity,
    // ... spread rate fields
}
#+end_src

** Error Handling

Public API boundaries return =Result=:
#+begin_src rust
pub fn calculate_spread_rate(&mut self) -> Result<f64, BehaveError> {
    if self.fuel_model == 0 {
        return Err(BehaveError::InvalidFuelModel(0));
    }
    // ... calculation
    Ok(spread_rate)
}
#+end_src

Internal methods can use =f64= directly when inputs are already validated.

** Data Tables

Static fuel model data as =const= arrays:
#+begin_src rust
pub const STANDARD_FUEL_MODELS: &[FuelModelRecord] = &[
    FuelModelRecord { number: 1, code: "FM1", name: "Short grass", /* ... */ },
    FuelModelRecord { number: 2, code: "FM2", name: "Timber grass and understory", /* ... */ },
    // ...
];
#+end_src

For keyed lookups, consider =phf= (compile-time hash maps).

** Builder Pattern for Complex Inputs

Replace C++ batch setter methods:
#+begin_src rust
let inputs = SurfaceInputsBuilder::new()
    .fuel_model(1)
    .moisture_one_hour(0.06)
    .moisture_ten_hour(0.07)
    .wind_speed(5.0, SpeedUnits::MilesPerHour)
    .slope(30.0, SlopeUnits::Percent)
    .build()?;
#+end_src
